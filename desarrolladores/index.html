Los datos del jardín, desde tu código

La API de CuFlora deja leer plantas, taxonomía, mapas, reportes y mediciones desde R, Python o cualquier sistema, con una llave de solo lectura. Para análisis, tableros o integrar el inventario con otros portales.

Empezar Ver la referencia

Empieza en tres pasos

De no tener nada a tu primera respuesta en unos minutos.

  1. Ten una cuenta de investigador

    Las llaves las crean investigadores y administradores. Si tu cuenta es de otro tipo, pide el cambio en claudio.rodriguez4333@alumnos.udg.mx.

  2. Crea una llave en la app

    En la app o en su versión web: Perfil → Llaves de API → Nueva llave. Ponle un nombre, elige qué puede leer y cópiala: solo se muestra una vez.

  3. Haz tu primera petición

    Guarda la llave en una variable de entorno y pide las plantas con su especie:

# Linux, macOS o Git Bash
export CUFLORA_KEY="cuf_…"

curl -H "Authorization: Bearer $CUFLORA_KEY" \
  "https://cuflora.kawi.page/plants?pageSize=100&in.species=true"

Tu llave

Trátala como una contraseña.

Tiene la forma cuf_<prefijo>_<secreto> y viaja en el encabezado Authorization: Bearer cuf_…. El prefijo la identifica en tu lista; el secreto solo existe en tu copia, porque CuFlora guarda únicamente su huella.

  • Solo lectura. Ninguna llave puede crear, editar ni borrar, aunque tu cuenta sí pueda.
  • Sin cuentas ni suscripciones. Usuarios, roles, suscriptores y notificaciones quedan fuera.
  • Caduca. Dura hasta 365 días; para renovarla, crea otra y revoca la vieja.
  • Sigue a tu cuenta. Si pierdes un permiso o se suspende tu cuenta, la llave deja de poder usarlo en ese momento.
  • Revócala si se filtra. Desde la misma pantalla de la app; deja de funcionar en el acto.
No la subas a un repositorio. Léela de una variable de entorno (CUFLORA_KEY) o de un archivo que esté en tu .gitignore.

Paginación, filtros y relaciones

Todos los listados funcionan igual. La referencia dice qué filtros y relaciones acepta cada uno.

Paginación

Los listados responden por páginas con pageNumber (desde 1) y pageSize (25 por omisión, 100 como máximo con llave). La respuesta trae los registros en data y dónde estás en pagination:

{
  "data": [ { "id": 12, "scientificName": "Agave tequilana", … } ],
  "pagination": { "pageNumber": 1, "pageSize": 100, "totalCount": 240,
                  "totalPages": 3, "hasNextPage": true, "hasPreviousPage": false }
}

El orden es fijo, así que puedes recorrer las páginas sin que se repitan ni falten registros: las plantas van por nombre común y luego científico, las familias y los géneros por nombre, los reportes del más reciente al más antiguo, y todo lo demás por id.

Filtros

Se escriben fi.<campo>_<operador>=valor. El operador siempre va: fi.speciesId=3 responde 400.

Operadores: eq, neq, gt, gte, lt, lte, between, in, not-in, contains, starts-with, ends-with, is-null, is-not-null.

GET /plants?fi.speciesId_eq=3
GET /reports?fi.subjectId_eq=12&pageSize=100

Relaciones (includes)

Por omisión cada registro llega solo, con los ids de sus relaciones. in.<relación>=true trae la relación en la misma respuesta. Úsalos en vez de pedir el detalle de cada registro: una página con in.species=true cuesta una petición; cien detalles, cien.

GET /plants?pageSize=100&in.species=true&in.placementZone=true

Coordenadas

Las coordenadas de una planta llegan con in.placementMap=true, en placement.position ({ "lat": …, "lng": … }, WGS84). placement.positionSource dice de dónde salen:

  • pixel: el punto marcado sobre la ortofoto georreferenciada. Es la más exacta.
  • gps: la media de las lecturas GPS tomadas en campo, cuando la planta no tiene punto en el mapa.

Una planta asignada solo a una zona, sin punto ni lecturas GPS, trae position: null. Las lecturas de campo también vienen aparte, en placement.latitude y placement.longitude, para que puedas compararlas con el punto del mapa.

GET /plants?pageSize=100&in.species=true&in.placementMap=true

Límites

Para que un script no deje sin servicio a quienes usan la app en campo. Se cuentan por llave, en toda la API.

120 / minutoPeticiones por llave, en ráfaga. Unas 2 por segundo.
3,000 / horaPeticiones por llave, sostenidas.
10 / horaExportaciones CSV por llave: cada una lee todo.
pageSize ≤ 100Registros por página. Si pides más, recibes 100.

Al pasarte, la respuesta es 429 con el encabezado Retry-After: los segundos que debes esperar. Respétalo y reintenta:

import os, time, requests

def cuflora(ruta, **params):
    url = "https://cuflora.kawi.page" + ruta
    headers = {"Authorization": f"Bearer {os.environ['CUFLORA_KEY']}"}
    while True:
        r = requests.get(url, params=params, headers=headers)
        if r.status_code != 429:
            r.raise_for_status()
            return r.json()
        time.sleep(int(r.headers.get("Retry-After", "5")))

# Todas las plantas, página por página
plantas, pagina = [], 1
while True:
    respuesta = cuflora("/plants", pageSize=100, pageNumber=pagina, **{"in.species": "true"})
    plantas += respuesta["data"]
    if not respuesta["pagination"]["hasNextPage"]:
        break
    pagina += 1

El servidor está dentro de la red universitaria y su enlace es lento para archivos grandes: una ortofoto puede tardar minutos. Guarda en disco lo que ya bajaste.

Errores

Todos responden JSON con statusCode y message.

400Parámetro mal escrito, por ejemplo un filtro sin operador.
401La llave no existe, está revocada o caducó.
403La llave no permite esa ruta: no está entre lo que puede leer, tu cuenta perdió el permiso o la ruta no acepta llaves.
404No hay registro con ese id.
429Pasaste un límite. Espera lo que diga Retry-After.
503Un servicio interno no respondió. Reintenta en unos segundos.
